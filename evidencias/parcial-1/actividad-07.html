Actividad 07 · Laboratorio FPT 01

Explotando un Path Traversal con Burp Suite

Documentación del laboratorio “File path traversal, simple case”: interceptación de la solicitud, manipulación controlada del parámetro filename y validación del resultado.

  • Estado: completado
  • Fecha: 18/09/2026
  • Nivel: Apprentice
  • Reporte: 10 páginas

01 / OBJETIVO

Comprobar una lectura de archivos fuera del directorio permitido

La práctica consistió en identificar el parámetro utilizado para cargar imágenes y modificarlo dentro de Burp Suite Repeater. El objetivo técnico fue recuperar el archivo /etc/passwd mediante una secuencia de recorrido de directorios y confirmar que el laboratorio reconociera la solución.

Entorno autorizado: la prueba se realizó exclusivamente dentro del laboratorio interactivo de PortSwigger Web Security Academy. El contenido se publica con fines académicos y defensivos.

02 / PROCEDIMIENTO

Del tráfico de imágenes a la petición manipulada

  1. Preparación: se inició Burp Suite Community con un proyecto temporal y el navegador integrado.
  2. Observación: se filtró el historial HTTP hasta localizar una solicitud GET /image?filename=....
  3. Repetición: la petición se envió a Repeater para modificar únicamente el parámetro vulnerable.
  4. Payload: se utilizó ../../../etc/passwd sin espacios adicionales.
  5. Validación: la respuesta HTTP/2 200 OK mostró el contenido solicitado y PortSwigger cambió el estado a Solved.

03 / RESULTADO

FPT 01 completado y validado

Vector

El parámetro filename aceptó una ruta relativa sin una validación suficiente del destino final.

Respuesta

El servidor devolvió estado 200 y expuso el contenido de un archivo fuera del directorio previsto para imágenes.

Evidencia

El reporte conserva la solicitud en Repeater, la respuesta del servidor y la pantalla oficial con el indicador Lab Solved.

Progreso

Este resultado desbloquea el primer nodo de seis dentro del camino Road to Hall of Fame.

04 / INCIDENCIAS

Errores detectados y correcciones aplicadas

  • 1
    Filtro de tráfico

    La configuración inicial de Burp ocultaba algunas solicitudes de imágenes; se ajustó la vista para localizar el recurso vulnerable.

  • 2
    Espacios en el payload

    El primer intento incluyó espacios y produjo un error 400 con el mensaje “No such file”. Se eliminó el espacio sobrante y se repitió la solicitud.

  • 3
    Confirmación independiente

    Además de inspeccionar la respuesta, se regresó a la página del laboratorio para comprobar el cambio oficial de estado a Solved.

05 / MITIGACIÓN

Controles para prevenir Path Traversal

  • ✓
    Lista permitida

    Aceptar solamente nombres o identificadores de archivo previamente autorizados.

  • ✓
    Ruta canónica

    Resolver la ruta final y comprobar que permanezca dentro del directorio autorizado antes de abrir el archivo.

  • ✓
    Identificadores indirectos

    Mapear un ID interno a un recurso, en lugar de recibir rutas proporcionadas directamente por el usuario.

  • ✓
    Mínimo privilegio

    Ejecutar el servicio con permisos restringidos para limitar el impacto de una lectura no autorizada.

08 / CONCLUSIÓN

Aprendizaje obtenido

El laboratorio demostró de forma práctica cómo una entrada no validada puede permitir la lectura de archivos sensibles. El uso combinado de Proxy y Repeater ayudó a relacionar la solicitud visible con el comportamiento del servidor, mientras que los intentos fallidos reforzaron la importancia de revisar con precisión la sintaxis y validar el resultado con más de una evidencia.
