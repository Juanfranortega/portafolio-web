Actividad 08 · Laboratorio FPT 02

Bypass de filtro mediante ruta absoluta

Documentación del laboratorio “File path traversal, traversal sequences blocked with absolute path bypass”: análisis del filtro, manipulación controlada de filename y validación de una lectura arbitraria con /etc/passwd.

  • Estado: completado
  • Fecha: 21/09/2026
  • Nivel: Practitioner
  • Evidencias: 8 capturas

01 / OBJETIVO

Evadir el bloqueo de secuencias de traversal con una ruta absoluta

La práctica consistió en identificar la solicitud que carga las imágenes de producto y comprobar que el filtro rechazaba el enfoque relativo, pero permitía entregar directamente una ruta absoluta. El objetivo técnico fue recuperar el contenido de /etc/passwd mediante el parámetro filename y confirmar la resolución oficial del laboratorio.

Entorno autorizado: la prueba se realizó exclusivamente dentro del laboratorio interactivo de PortSwigger Web Security Academy. El procedimiento se documenta con fines académicos y defensivos.

02 / FUNDAMENTACIÓN TÉCNICA

El filtro bloquea el patrón, no el destino real

La aplicación espera un nombre de imagen relativo a su directorio de trabajo y filtra secuencias como ../. Esa defensa no verifica si la entrada ya representa una ruta absoluta. Al recibir /etc/passwd, el sistema operativo comienza la resolución desde la raíz del sistema de archivos y omite por completo el directorio base de imágenes.

Clasificación

La falla corresponde a CWE-22 y se vincula con OWASP A01: Broken Access Control, porque permite acceder a un recurso fuera del límite previsto.

Causa raíz

La validación usa una lista de bloqueo para buscar ../, pero no canonicaliza la ruta ni comprueba que el destino final permanezca dentro del directorio autorizado.

Impacto CIA

El resultado demostrado afecta la confidencialidad. En funciones equivalentes de escritura o eliminación, el mismo error también podría afectar integridad y disponibilidad.

Diferencia con FPT 01

El primer laboratorio escapó con segmentos relativos. FPT 02 alcanza el mismo archivo sin navegar directorios: entrega la ruta completa desde la raíz.

03 / PROCEDIMIENTO · PREPARACIÓN

Acceso al reto y generación de tráfico

  1. Iniciar el entorno: se abrió Burp Suite Community Edition con un proyecto temporal y su configuración predeterminada.
  2. Abrir el navegador integrado: desde Proxy se utilizó el navegador de Burp para enrutar automáticamente las solicitudes del laboratorio.
  3. Leer la consigna: PortSwigger indicó que las secuencias de traversal estaban bloqueadas y que la meta era recuperar /etc/passwd.
  4. Acceder a la tienda: se recorrieron los productos para provocar solicitudes de imágenes y registrar tráfico suficiente en HTTP history.

04 / PROCEDIMIENTO · CAPTURA

Corrección del filtro y selección de filename

  1. Detectar el problema: la configuración inicial de HTTP history ocultaba CSS, imágenes y extensiones específicas, por lo que las peticiones relevantes no aparecían.
  2. Corregir el filtro: se habilitó el tipo MIME de imágenes y se retiraron las extensiones de imagen del campo de exclusión.
  3. Localizar la solicitud: se seleccionó GET /image?filename=1.jpg y se verificó la respuesta JPEG original.
  4. Enviar a Repeater: desde el menú contextual se copió la petición a Repeater para editarla y reenviarla de forma controlada.

05 / PROCEDIMIENTO · EXPLOTACIÓN

Sustitución por /etc/passwd y validación

  1. Conservar una línea base: Repeater recibió la solicitud original GET /image?filename=1.jpg.
  2. Modificar únicamente la entrada: el valor de filename se reemplazó por la ruta absoluta /etc/passwd, sin secuencias ../.
  3. Enviar la petición: el servidor devolvió HTTP/2 200 OK y líneas con el formato característico del archivo de cuentas de Linux.
  4. Comprobar el resultado: al actualizar la página oficial, el indicador cambió de Not solved a Solved.

06 / EXPLICACIÓN DEL PAYLOAD

/etc/passwd, ruta absoluta desde la raíz

/

La barra inicial indica que la resolución comienza en la raíz del sistema de archivos. Por ello, la ruta ya no depende del directorio de imágenes de la aplicación.

etc

Es el directorio estándar de configuración en sistemas Linux y Unix. La aplicación vulnerable permite salir de su contexto lógico sin utilizar ../.

passwd

Es un archivo de texto con información de cuentas locales. La presencia de líneas como root:x:0:0:... demuestra que se leyó el recurso solicitado.

Condición de éxito

El código 200, el cuerpo del archivo y el cambio a Solved forman una validación técnica y funcional del bypass.

Tipo de explotación: lectura arbitraria de archivos mediante bypass con ruta absoluta. No hubo ejecución de comandos, alteración de datos ni acceso fuera del laboratorio autorizado.

08 / MITIGACIÓN

Validar el destino, no solo bloquear cadenas

  • 1
    Usar identificadores indirectos

    Recibir un ID y resolverlo en el servidor evita que el cliente controle nombres o rutas del sistema de archivos.

  • 2
    Lista permitida estricta

    Aceptar únicamente nombres y extensiones esperados; rechazar separadores, rutas absolutas y valores fuera del formato definido.

  • 3
    Canonicalización y confinamiento

    Obtener la ruta real con una función equivalente a realpath() y comprobar que el resultado esté dentro del directorio autorizado.

  • 4
    Validación multiplataforma

    Considerar rutas absolutas Unix que comienzan con /, rutas Windows con letra de unidad y variantes de separadores.

  • 5
    Mínimo privilegio

    Ejecutar el servicio con una cuenta restringida y separar los archivos sensibles para reducir el impacto de una validación fallida.

  • 6
    Pruebas automatizadas

    Probar rutas relativas, absolutas, codificadas y normalizadas para verificar el confinamiento en cada cambio de la aplicación.

12 / CONCLUSIÓN

Aprendizaje obtenido

El laboratorio mostró que bloquear una cadena conocida no equivale a controlar el acceso a archivos. La ruta absoluta evitó por completo la secuencia que el filtro buscaba y permitió llegar al mismo recurso sensible. La práctica reforzó que la defensa correcta debe canonicalizar la entrada, comprobar el directorio final y aplicar privilegios mínimos, en lugar de depender únicamente de una lista de patrones prohibidos.
